## Contexte Recovery-Branch

### Qu'est-ce qu'une Recovery Branch?

Une branche de recovery est généralement créée pour:
- Récupérer du code fonctionnel après des changements cassants
- Servir de checkpoint stable avant une refactorisation majeure
- Préserver un état connu comme fonctionnel
- Faciliter la récupération en cas d'erreur sur main/develop

**Hypothèse pour ANZAR:**
La recovery-branch contient probablement le dernier état stable et fonctionnel de l'application avant une tentative de migration ou refactorisation qui a échoué.

### 🟠 Issue #4: Pas de Gestion d'Erreurs

#### Symptôme
Aucun try-catch ou error boundary visible dans `app.js`.

#### Risques
- ❌ Crash silencieux du graphe D3
- ❌ Erreur localStorage = perte de data
- ❌ Erreur indexedDB = corruption
- ❌ Erreur parsing markdown = rendu cassé

#### Solution

```javascript
// Envelopper les opérations critiques
try {
    await openDB();
} catch (error) {
    console.error('Database initialization failed:', error);
    showErrorUI('Database unavailable. Using memory only.');
}

// Wrapper pour localStorage
function safeGet(key) {
    try {
        const data = localStorage.getItem(key);
        return data ? JSON.parse(data) : null;
    } catch (error) {
        console.error('Storage read error:', error);
        return null;
    }
}

// Error boundary pour render
try {
    view.innerHTML = html;
} catch (error) {
    console.error('Render error:', error);
    view.innerHTML = '<div class="error">Failed to render view</div>';
}
```

### 🟠 Issue #5: Performance Non Optimisée

#### Problèmes Identifiés

1. **Search sans debounce**
```javascript
   // ❌ Actuellement: Déclenche à chaque keystroke
   searchInput.addEventListener('input', () => {
       this.renderFileTree(view);  // Rend toute l'arborescence!
   });

   // ✅ Solution: Debounce
   const debounce = (fn, delay) => {
       let timeout;
       return (...args) => {
           clearTimeout(timeout);
           timeout = setTimeout(() => fn(...args), delay);
       };
   };

   searchInput.addEventListener(
       'input',
       debounce(() => this.renderFileTree(view), 300)
   );
```

2. **D3.js non minifié**
   - Charger depuis CDN complet (~500KB)
   - ✅ Solution: Lazy load seulement sur Graph tab

3. **Pas de code splitting**
   - Tout chargé au démarrage
   - ✅ Solution: Lazy load modules par vue

4. **Service worker caching statique**
   - Cache tous les fichiers d'emblée
   - ✅ Solution: Cache dynamique ou stale-while-revalidate

#### Logique d'Extraction de Liens

```javascript
// Extraction depuis contenu note
const nodes = this.data.notes.map(note => ({
    id: note.id,
    title: note.title,
    tags: note.tags || [],
    radius: 8 + (note.links?.length || 0) * 2
}));

const links = [];
this.data.notes.forEach(note => {
    (note.links || []).forEach(linkTitle => {
        const target = this.data.notes.find(
            n => n.title.toLowerCase() === linkTitle.toLowerCase()
        );
        if (target && target.id !== note.id) {
            links.push({ source: note.id, target: target.id });
        }
    });
});
```

#### D3 Force Simulation

```javascript
const simulation = d3.forceSimulation(nodes)
    .force('link', 
        d3.forceLink(links)
            .id(d => d.id)
            .distance(100)
    )
    .force('charge', 
        d3.forceManyBody()
            .strength(-300)  // Repulsion
    )
    .force('center', 
        d3.forceCenter(width / 2, height / 2)
    )
    .force('collision', 
        d3.forceCollide()
            .radius(d => d.radius + 5)  // Pas d'overlap
```
